# 정책보고서 작성 · 6단계 채팅 가이드

기존 정책보고서 프롬프트 가이드의 카드와 좌우 입력창 디자인을 활용한 정적 웹사이트입니다. 첫 화면에서 **강사용 / 수강생용**을 선택합니다. 수강생 실습은 **작성 요령 → 입력·프롬프트 → 내 결정 기록**의 세 메뉴로 구성하며, 설명 화면과 입력 화면을 분리했습니다. 강사용에는 PDF 슬라이드쇼와 모든 단계의 입력·결정·결과가 준비된 교육용 사례를 제공합니다. 모든 실습 단계를 하나의 AI 채팅에서 이어서 진행하며, 앞선 대화의 결과와 사용자가 확정한 결정을 활용합니다. ② 자료 수집·분석은 조사계획과 조사·해석 결과 정리의 두 과정으로 진행합니다.

- 공개 저장소: https://github.com/ankiyong/policy-report-six-steps
- GitHub Pages: https://ankiyong.github.io/policy-report-six-steps/

## 강사·수강생 입장

| 주소 | 용도 |
| --- | --- |
| `index.html` | 강사용·수강생용 입장 선택 |
| `practice.html` | 수강생의 빈 입력창으로 시작하는 실습 |
| `instructor.html` | 첨부 강의안의 슬라이드쇼와 강사용 실습 진입 |
| `practice.html?mode=instructor` | 완성된 예시 입력·프롬프트·결정 기록·단계 결과를 활용하는 강사용 실습 |

강사용과 수강생용 구분은 화면과 시작 자료를 나누는 기능입니다. 로그인이나 접근 권한 검사가 아니므로 공개 주소를 아는 사람은 어느 쪽으로도 입장할 수 있습니다. 강사가 작성한 내용이 수강생 페이지에 실시간으로 전달되지는 않습니다.

강의용 사례는 **“순환보직에 따른 인수인계 미비”를 AI 활용으로 개선하는 정책보고서**입니다. ① 문제 설정부터 ②-1 조사계획, ②-2 자료·해석, ③ 대안, ④ 실행 가능성, ⑤ 추진계획, ⑥ 최종 보고서까지 이어집니다. 각 단계의 입력과 결정 기록을 미리 채우고 프롬프트를 완성해 두었으며, 강사용 **완성 예시** 화면에서 결과와 결정 반영 내용을 확인·복사할 수 있습니다. 입력을 수정하면 프롬프트를 다시 생성해야 합니다. 완성 예시는 실시간 AI 응답이 아니라 사전에 작성한 수업 자료입니다.

사례의 기관·자료·검토 결과와 수치·일정·목표는 **교육용 가정 또는 제안**입니다. 실제 기관의 조사 결과나 승인·확보된 법적 근거·예산·협의로 인용하지 않습니다. 현실에 적용할 때는 기관 자료와 원문을 확인하고 각 조건을 새로 판단해야 합니다. 수강생 입력창에는 이 사례를 자동으로 채우지 않습니다.

입력은 각 브라우저 페이지의 메모리에만 유지합니다. 수강생은 새로고침 후 빈 입력으로, 강사는 새로고침 후 제공된 기본 예시로 시작합니다. 다른 사람의 입력이나 다른 페이지에서 수정한 값과 공유되지 않습니다.


## 구성

- 공통 지침 + ① 주제·문제 설정 + ② 자료 수집·분석 + ③ 개선방안 도출 + ④ 실행 가능성 검토 + ⑤ 추진계획 수립 + ⑥ 보고서 작성: 총 7개 카드
- 공통 지침 1개, ①·③~⑥ 단계 프롬프트 5개, ② 과정 프롬프트 2개, 각 단계의 내 결정 기록 6개: 총 14개 프롬프트
- 각 단계의 작성 요령 화면에 목표, 핵심 원칙과 설명, 연결되는 교육용 예시, 점검 항목, 준비할 자료·정보 제공
- ①·③~⑥에는 공통 문구 자동 포함, ②-1·②-2에는 사용자 제공 과정별 작성 지침 포함
- 단계별 “작성 요령”, “입력·프롬프트”, “내 결정 기록” 메뉴와 항목별 입력 안내, 생성 및 복사
- ②는 “②-1 조사계획 수립” → 직접 조사 → “②-2 조사·해석 결과 정리” 순서로 진행하며 두 과정 각각의 작성 요령과 입력 화면 제공
- ②-2는 자료별 입력 묶음을 추가·삭제해 여러 자료의 사실·출처·내 해석을 각각 입력
- 넓은 화면에서는 입력 영역과 템플릿·완성 프롬프트를 좌우에 배치하고 각각 스크롤
- 이전·다음 단계 이동, 기본 프롬프트 TXT 다운로드, 모바일 화면과 키보드 탐색 지원
- `practice.html#step-2` 등 단계 주소 공유 가능

## 사용 방법

1. **공통 지침**을 읽고 자료와 내 판단, 확인된 사실과 AI 제안을 구분하는 원칙을 확인합니다. ①·③~⑥에는 공통 문구, ②-1·②-2에는 과정별 작성 지침이 이미 포함되므로 별도로 덧붙일 필요가 없습니다.
2. 단계 카드를 열면 **작성 요령** 화면에서 목표, 원칙, 예시와 준비할 자료·정보를 확인할 수 있습니다. **입력·프롬프트** 메뉴로 이동해 항목별 안내를 참고하며 입력창을 채웁니다. 입력 화면으로 바로 이동하거나 작성 요령을 다시 볼 수 있으며, 설명과 입력 화면을 오가도 작성 중인 내용이 유지됩니다. ②는 **②-1 조사계획 수립**에서 먼저 조사 범위와 질문을 입력합니다. 모르는 정보는 `확인 필요`, 해당하지 않는 항목은 `해당 없음`으로 적습니다.
3. **프롬프트 생성**을 누르면 템플릿의 입력 자리에 작성한 정보가 들어갑니다. 완성된 본문을 확인하고 **프롬프트 복사**를 눌러 ①을 시작한 AI 채팅에 계속 붙여 넣습니다. 실제 자료 파일은 AI 채팅에 직접 첨부합니다. ②-1의 제안을 검토해 조사 대상을 정하고 직접 자료 검색·원문 확인·첫 해석을 수행한 뒤, **②-2 조사·해석 결과 정리**에 자료별 정보를 입력합니다. 생성한 ②-2 프롬프트는 **②-1과 같은 AI 채팅**에 붙여 넣습니다.
4. AI 답변을 읽고 **내 결정 기록** 메뉴에서 선택·확정한 사항과 이유, 수정·제외할 사항, 보류·추가 확인할 사항을 입력합니다. 생성한 결정 문구를 앞선 단계를 진행한 같은 AI 채팅에 보냅니다.
5. AI가 갱신한 **단계 결과 요약**을 확인한 뒤 다음 단계도 같은 AI 채팅에서 진행합니다. 각 프롬프트는 앞선 대화의 결과와 확정한 결정을 이어서 활용하도록 구성되어 있습니다. 새로 필요한 근거 자료만 추가로 첨부합니다.
6. ⑥ 보고서 작성에서도 내 결정 기록을 사용해 최종 확인 사항을 명시하고, 실제 기관 양식의 줄 수와 페이지 배치를 확인합니다.

이전 단계 요약이나 채팅 이름을 다시 입력하는 항목은 없습니다. 결정 기록은 단계마다 별도로 입력·생성합니다. 선택한 방안과 그 방안의 효과·비용·실행 조건이 확인되었는지는 구분합니다. 내 결정 기록은 해당 단계의 후속 요청이므로 공통 문구를 다시 반복하지 않습니다.

생성 후 입력을 수정하면 다시 생성해야 복사할 수 있습니다. 입력과 생성 결과는 현재 페이지 안에서 작성 요령·입력·내 결정 기록을 오가거나, 단계·과정을 이동하거나, 창을 닫았다 열어도 유지되지만, **새로고침하거나 페이지를 닫으면 초기화됩니다.** 강사용에서는 준비된 기본 예시가 다시 채워집니다. 입력값은 페이지 메모리에서만 처리하며 로컬 저장소에 저장하거나 서버로 전송하지 않습니다. AI API를 직접 호출하지 않으므로 생성 버튼은 AI 답변이 아닌 복사할 프롬프트 본문을 만듭니다. 접속자마다 자신의 브라우저에서 독립적으로 사용합니다.

작성 요령과 예시는 학습을 위한 화면 안내이며 기본 프롬프트에 자동으로 덧붙이지 않습니다. 예시는 “청년 지원사업 모집공고의 신청정보 안내 개선”을 단계별로 이어가며 실제 조사 결과나 확정된 법·예산·일정을 의미하지 않습니다. 입력은 사용자의 실제 상황과 판단으로 작성합니다.

**전체 프롬프트 TXT 다운로드**는 사용자가 입력한 내용이 없는 기본 템플릿입니다. 공통 문구, ①·③~⑥ 단계 프롬프트, ②-1·②-2의 과정별 프롬프트, 반복 사용하는 내 결정 기록이 들어 있습니다.

## 먼저 열어보기

`index.html`을 브라우저에서 엽니다. 별도 설치나 빌드는 필요하지 않습니다. 폴더 구조를 유지해야 이미지·스타일·스크립트가 정상 표시됩니다. 브라우저에서 복사가 제한되면 화면 안내에 따라 선택된 내용을 Ctrl+C 또는 ⌘C로 복사하고, 모바일에서는 내용을 길게 눌러 복사합니다.

## GitHub Pages 배포

공개 저장소 `ankiyong/policy-report-six-steps`의 `master` 브랜치 루트에서 배포합니다.

1. 저장소 최상위에 입장 화면 `index.html`, 실습 화면 `practice.html`, 강의 화면 `instructor.html`, `.nojekyll`, `assets`, `images`, 강의 PDF, `prompts.txt`, `content-plan.json`, `README.md`, `LICENSE.txt`, `TEMPLATE_README.txt`를 업로드하고 커밋합니다. HTML·스크립트에서 사용하는 강의 이미지와 예시 데이터를 함께 배포해야 합니다.
2. 저장소의 **Settings → Pages → Build and deployment**에서 **Source → Deploy from a branch**, **Branch → master**, **폴더 → /(root)**를 선택합니다.
3. 배포가 완료되면 Pages 주소에서 두 입장 경로, 강의 슬라이드 이동·전체 화면, 수강생의 빈 입력, 강사용의 완성된 예시, 프롬프트 생성·복사, 내 결정 기록과 단계 이동을 확인합니다.

이미지 시안·원본과 검토용 보드를 담은 `output` 폴더, ZIP 파일은 배포 대상에서 제외합니다. `tests` 폴더는 로컬 검증용입니다.

공식 배포 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

| --- | --- |

| `assets/js/prompts.js` | 실제 화면에서 사용하는 카드 정보와 14개 프롬프트 |
| `assets/js/writing-guides.js` | 7개 과정별 작성 요령·설명·교육용 예시·점검 항목과 입력 항목별 한 줄 안내 |
| `assets/js/prompt-builder.js` | 입력 항목 추출과 입력값 치환 |
| `assets/js/guide.js` | 카드·대화상자·작성 요령 및 입력 화면 표시, 입력과 생성·복사, 페이지 내 상태 |
| `assets/js/instructor-data.js` | 강사용 가상 사례의 항목별 입력, 자료별 기록, 단계·결정 결과, 최종 보고서 |
| `assets/css/guide.css` | 색상·글꼴·카드·대화상자·반응형 배치 |
| `index.html` | 강사용·수강생용 입장 선택 |
| `practice.html` | 기존 실습 화면과 강사용 완성 예시 화면 |
| `instructor.html` | 강의안 슬라이드쇼와 강사용 실습 연결 |
| `images/steps/common.webp`, `step-1.webp`~`step-6.webp` | 공통 지침과 6개 단계 이미지 |
| `prompts.txt` | 다운로드용 기본 문안 |

프롬프트를 수정하면 `content-plan.json`, `prompts.js`, `prompts.txt`를 함께 맞춰 주세요. 한 채팅에서 이어가는 방식에 맞춰 이전 단계 요약 입력을 제거하고 앞선 대화를 활용하도록 조정했으며, 그 외 사용자 제공 프롬프트 내용은 유지합니다. ①·③~⑥의 메인 프롬프트는 각 단계 원문 뒤에 공통 문구를 결합합니다. ②의 `processes`에는 과정별 작성 지침을 포함한 원문을 저장하며 공통 문구를 중복으로 덧붙이지 않습니다. 런타임의 `step-2-plan`과 `step-2-analysis`는 각각 해당 원문을 `text`로 사용합니다. `repeatSection`은 자료별로 반복할 입력 영역을 가리킵니다. 결정 프롬프트는 공통 결정 문구를 단계마다 독립적으로 사용합니다.

`writing-guides.js`의 `window.WRITING_GUIDES`는 과정 프롬프트 ID를 키로 사용합니다. 각 과정에 `goal`, `rules`, `examples`, `checkpoints`, `fieldHints`를 제공하며, `fieldHints`의 키는 실제 프롬프트 입력 항목명과 일치해야 합니다. 작성 요령을 수정할 때는 사용자 입력과 기존 프롬프트를 바꾸지 않고 안내 데이터만 수정할 수 있습니다.
