# 정책보고서 작성 · 수강생 6단계 / 강사 7단계 가이드

기존 정책보고서 프롬프트 가이드의 카드와 좌우 입력창 디자인을 활용한 정적 웹사이트입니다. 첫 화면에서 **강사용 / 수강생용**을 선택합니다. 수강생에게는 ①~⑥만 표시하며 **작성 요령 → 입력·프롬프트 → 내 결정 기록**의 세 메뉴로 설명과 입력 화면을 분리했습니다. 강사용은 비밀번호 확인 후 PDF 슬라이드쇼와 ①~⑦의 교육용 사례를 제공합니다. 강사용 ⑦은 **작성 요령 → 프롬프트**에서 확정된 문안을 바로 복사하는 단계입니다. ①~⑥은 하나의 AI 채팅에서 이어서 진행하며, 앞선 대화의 결과와 사용자가 확정한 결정을 활용합니다. ② 자료 수집·분석은 조사계획과 조사·해석 결과 정리로, ③ 개선방안 도출은 AI와 아이디어 5개를 탐색한 뒤 사람이 1개를 선택·구체화하는 두 과정으로 진행합니다. ⑥ 보고서 작성은 개요 초안 작성과 확정 개요를 바탕으로 한 본문 초안 작성으로 나눕니다. 강사용 ⑦에서는 최신 확정 원고와 빈 HWPX 양식을 Claude에 전달하고, hwpx-writer 스킬로 양식 작성·검증·수정 후 편집 가능한 HWPX 파일의 다운로드를 요청합니다.

## 강사·수강생 입장

| 주소 | 용도 |
| --- | --- |
| `index.html` | 강사용·수강생용 입장 선택 |
| `practice.html` | 수강생의 빈 입력창으로 시작하는 ①~⑥ 실습 |
| `instructor-login.html` | 강사용 비밀번호 확인 및 원래 요청한 강사용 화면으로 이동 |
| `instructor.html` | 인증 후 사용하는 첨부 강의안 슬라이드쇼와 강사용 실습 진입 |
| `practice.html?mode=instructor` | 인증 후 완성된 예시 입력·프롬프트·결정 기록·단계 결과를 활용하는 ①~⑦ 강사용 실습 |
| `practice.html?mode=instructor&process=body#step-6` | 강사용 본문 초안·최종 점검 예시 바로가기 |
| `practice.html?mode=instructor#step-7` | 강사용 Claude 양식 작성·검증·다운로드 진행 예시 |

수강생은 비밀번호 없이 ①~⑥을 사용합니다. 수강생 화면에서는 ⑦ 카드·이동·안내를 표시하지 않으며 `practice.html#step-7`로 직접 들어와도 해당 창을 열지 않습니다. 강사용 화면은 비밀번호 확인 후 사용할 수 있고, 강사용 주소로 직접 접근해도 인증을 먼저 확인합니다. 강사용 인증 상태만 현재 탭의 `sessionStorage`에 유지하며 로그아웃하면 해제합니다. 보고서 입력은 이 인증 상태와 별개로 페이지 메모리에서만 유지합니다. 강사가 작성한 내용이 수강생 페이지에 실시간으로 전달되지는 않습니다.

이 비밀번호 확인은 공개 정적 사이트에서 강사용 입장 흐름을 구분하는 편의 기능입니다. 서버에서 자료 접근을 차단하는 보안 장치가 아니며 공개 저장소와 배포된 JavaScript·자료 파일은 확인할 수 있습니다. 기밀 자료 보호 용도로 사용하지 않습니다. 실제 비밀번호는 문서나 테스트에 기록하지 않습니다.

강의용 사례는 **“순환보직에 따른 인수인계 미비”를 AI 활용으로 개선하는 정책보고서**입니다. ① 문제 설정부터 ②-1 조사계획, ②-2 자료·해석, ③-1 아이디어 5개 탐색, ③-2 한 가지 선택·구체화, ④ 실행 가능성, ⑤ 추진계획, ⑥-1 개요 초안, ⑥-2 본문 초안·최종 점검까지 이어집니다. 각 단계의 입력과 결정 기록을 미리 채우고 프롬프트를 완성해 두었으며, 강사용 **완성 예시** 화면에서 결과와 결정 반영 내용을 확인·복사할 수 있습니다. 입력을 수정하면 프롬프트를 다시 생성해야 합니다. 완성 예시는 실시간 AI 응답이 아니라 사전에 작성한 수업 자료입니다.

사례에서 인용한 공개 문서는 실제 출처와 링크를 제공합니다. 사례의 기관 상황·분석·검토 결과와 수치·일정·목표는 **교육용 가정 또는 제안**입니다. 공개 문서의 내용과 사례에 대한 해석을 구분하며, 이를 실제 기관의 조사 결과나 승인·확보된 예산·협의로 인용하지 않습니다. 현실에 적용할 때는 해당 원문의 내용·적용 범위·최신 여부를 확인하고 기관의 조건을 새로 판단해야 합니다. 수강생 입력창에는 이 사례를 자동으로 채우지 않습니다.

입력은 각 브라우저 페이지의 메모리에만 유지합니다. 수강생은 새로고침 후 빈 입력으로, 강사는 새로고침 후 제공된 기본 예시로 시작합니다. 다른 사람의 입력이나 다른 페이지에서 수정한 값과 공유되지 않습니다.

### 강의 슬라이드쇼

첨부한 `1234.pdf`의 10쪽을 순서와 내용을 유지해 슬라이드 이미지로 표시합니다. **이전·다음**, 슬라이드 화면의 **←·→ / Home·End**, **전체 슬라이드 보기**에서 선택할 수 있습니다. 자동 재생은 15·30·60초 간격을 선택하며 마지막 장에서 멈춥니다. 직접 이동하거나 다른 화면으로 전환하면 자동 재생을 중지합니다. 전체 화면을 지원하지 않는 브라우저에서는 페이지 안에서 크게 펼치며 Esc 또는 종료 버튼으로 돌아갑니다. `lecture.pdf`에서 원본 열기·다운로드도 제공합니다.

강의안의 7단계 중 마지막 **최종 점검**은 실습의 6단계 **보고서 작성**에 포함됩니다. 강사용 실습에 추가한 7단계는 **Claude로 첨부 양식에 보고서 작성**입니다. 강의안의 7단계와 강사용 실습 7단계는 서로 다른 구분이며, 10장 슬라이드 원문은 유지합니다.


## 구성

- 수강생은 공통 지침 + ① 주제·문제 설정 + ② 자료 수집·분석 + ③ 개선방안 도출 + ④ 실행 가능성 검토 + ⑤ 추진계획 수립 + ⑥ 보고서 작성: 총 7개 카드
- 인증한 강사는 위 카드에 ⑦ Claude로 첨부 양식에 보고서 작성을 추가: 총 8개 카드
- 공통 지침 1개, ①·④·⑤ 단계 프롬프트 3개, ②·③·⑥의 과정 프롬프트 각 2개, ①~⑥의 내 결정 기록 6개: 수강생 총 16개 프롬프트. 강사용은 ⑦의 문서 작업 프롬프트를 포함해 17개
- 수강생 9개·강사용 10개 작성 과정의 요령 화면에 목표, 핵심 원칙과 설명, 연결되는 교육용 예시, 점검 항목, 준비할 자료·정보 제공
- 모든 프롬프트 첫 줄에 현재 단계 번호·작업 이름 표시. 예: `# 5. 추진계획 수립`, `# 6-1. 개요 초안 작성`. 내 결정 기록도 해당 단계 제목 포함
- ①·③~⑥에는 공통 문구 자동 포함, ②-1·②-2에는 사용자 제공 과정별 작성 지침 포함
- 단계별 “작성 요령”, “입력·프롬프트”, “내 결정 기록” 메뉴와 항목별 입력 안내, 생성 및 복사
- ②는 “②-1 조사계획 수립”에서 AI에 공신력 있는 공개 문서 검색을 요청 → 사람이 원문 확인·분석 → “②-2 조사·해석 결과 정리” 순서로 진행하며 두 과정 각각의 작성 요령과 입력 화면 제공
- ②-1은 보고서 작성 주제·제목, 확인할 질문, 조사 범위, 판단하려는 사항의 5개 항목을 입력하며, 이미 확보한 자료와 조사 시간·제약은 입력받지 않음
- ②-2는 자료명, 출처 및 링크, 내가 분석한 내용, 본 주제와의 관련성, 해석하기 어려운 내용, 활용 판단의 6개 항목을 자료별로 추가·삭제
- ③-1은 해결할 문제, 달성할 변화, 비교 기준, 지킬 조건, 그 외 추가 사항의 5개 항목으로 AI와 개선 아이디어 5개를 탐색
- ③-2는 그중 1개를 선택하고 선택 이유, 사용자 보완 생각, 실행 대상·방법, 자원, 담당·시기, 어려움·확인 사항을 입력해 구체화
- ⑤는 대안·실행 순서·일정·완료 기준·역할·자원의 6개 입력을 받아 과업과 선행 조건, 산출물, 일정·책임을 연결하고 ④의 미결 사항을 준비 과업으로 전환
- ⑥-1은 지금까지 확정한 내용으로 **추진배경 및 문제점 → 개선방안 → 추진계획 → 기대 효과** 네 부분의 개요를 작성
- ⑥-2는 사용자가 확정한 개요의 순서·판단·근거를 유지해 개조식 본문 초안을 작성하고, 기관 양식과 논리 연결·불확실성을 별도로 점검
- 강사용 ⑦은 문안을 추가 입력 없이 바로 복사하며, 최신 확정 원고와 빈 HWPX 양식을 Claude에 전달 → hwpx-writer로 양식 복사본 작성 → 편집 가능한 표·내용·배치 검증 및 수정 → HWPX 다운로드를 요청
- 발행기관·작성자·발행 시점과 사실·수치·통계 기준은 사람이 별도로 입력하지 않고 AI가 채팅에 첨부한 원문에서 확인하도록 요청
- 넓은 화면에서는 입력 영역과 템플릿·완성 프롬프트를 좌우에 배치하고 각각 스크롤
- 이전·다음 단계 이동, 기본 프롬프트 TXT 다운로드, 모바일 화면과 키보드 탐색 지원
- `practice.html#step-2` 등 단계 주소 공유 가능

## 사용 방법

1. **공통 지침**을 읽고 자료와 내 판단, 확인된 사실과 AI 제안을 구분하는 원칙을 확인합니다. ①·③~⑥에는 공통 문구, ②-1·②-2에는 과정별 작성 지침이 이미 포함되므로 별도로 덧붙일 필요가 없습니다.
2. 단계 카드를 열면 **작성 요령** 화면에서 목표, 원칙, 예시와 준비할 자료·정보를 확인할 수 있습니다. **입력·프롬프트** 메뉴로 이동해 항목별 안내를 참고하며 입력창을 채웁니다. 입력 화면으로 바로 이동하거나 작성 요령을 다시 볼 수 있으며, 설명과 입력 화면을 오가도 작성 중인 내용이 유지됩니다. ②는 **②-1 조사계획 수립**에서 1단계에서 정한 보고서 작성 주제와 제목, 확인할 질문·조사 범위·판단하려는 사항을 입력합니다. 모르는 정보는 `확인 필요`, 해당하지 않는 항목은 `해당 없음`으로 적습니다.
3. **프롬프트 생성**을 누르면 템플릿의 입력 자리에 작성한 정보가 들어갑니다. 완성된 본문을 확인하고 **프롬프트 복사**를 눌러 ①을 시작한 AI 채팅에 계속 붙여 넣습니다. ②-1에서는 AI가 웹에서 정부·공공기관·학술자료 등 보고서 근거로 사용할 문서를 찾아 실제 문서명·공식 출처·링크와 확인 상태를 제시하도록 요청합니다. 사람이 원문을 읽고 자료 채택 여부와 자신의 분석을 정한 뒤, **②-2 조사·해석 결과 정리**에 자료별 정보를 입력합니다. 원문 파일은 **②-1과 같은 AI 채팅**에 직접 첨부하고 생성한 ②-2 프롬프트를 붙여 넣습니다. AI가 원문에서 발행정보와 사실·수치를 확인하며, 사용자의 분석과 AI 점검 의견을 구분합니다.
4. AI 답변을 읽고 **내 결정 기록** 메뉴에서 선택·확정한 사항과 이유, 수정·제외할 사항, 보류·추가 확인할 사항을 입력합니다. 생성한 결정 문구를 앞선 단계를 진행한 같은 AI 채팅에 보냅니다.
5. ①~⑥에서는 AI가 갱신한 **단계 결과 요약**을 확인한 뒤 다음 단계도 같은 AI 채팅에서 진행합니다. 해당 프롬프트는 앞선 대화의 결과와 확정한 결정을 이어서 활용하도록 구성되어 있습니다. 새로 필요한 근거 자료만 추가로 첨부합니다.
6. ⑥에서는 **⑥-1 개요 초안 작성**으로 네 부분의 개요를 먼저 작성합니다. 같은 AI 채팅에서 검토·수정하고 개요를 확정한 뒤 **⑥-2 본문 초안 작성**을 진행합니다. 내 결정 기록으로 최종 확인 사항을 명시하고, 실제 기관 양식의 줄 수와 페이지 배치를 확인합니다.
7. **강사용만:** ⑦의 **프롬프트** 메뉴에서 전체 문안을 바로 복사해 Claude에서 사용합니다. ⑥-2의 최신 확정 원고를 모든 표·주석·출처와 함께 전달하고 **빈 HWPX 양식을 반드시 첨부**합니다. 다른 AI 채팅의 내용은 Claude가 자동으로 읽을 수 없으므로 원고를 직접 붙여 넣거나 파일로 전달합니다. 이미 같은 Claude 대화에서 작성했다면 그 대화의 최신 확정 원고를 활용합니다. `@hwpx-writer` 스킬로 첨부 양식의 복사본에 내용을 작성하고 검증·수정 후 HWPX 다운로드를 요청합니다. 별도 입력창·생성 버튼·내 결정 기록은 없습니다. 강사용 **진행 예시**는 확인할 순서와 조건을 보여주는 수업 자료이며 실제 생성·검증한 파일이나 완료 결과가 아닙니다.

③에서는 먼저 **③-1 개선방안 아이디어 브레인스토밍**의 5개 입력창을 채웁니다. 완성된 아이디어를 미리 작성할 필요 없이 해결할 문제와 원하는 변화·판단 기준·제약을 적고, 추가 사항이 없으면 `없음`으로 입력합니다. 같은 AI 채팅의 ②-2 자료·분석과 확정된 판단을 바탕으로 서로 다른 개선 아이디어 5개를 함께 검토합니다. 각 아이디어가 해결할 문제와 바꾸는 내용, 실행 방법·조건·한계를 비교합니다. 이어 **③-2 개선방안 선택·구체화**에서 사람이 목록 중 1개를 선택하고 자신의 생각과 현실적인 조건을 더합니다. AI 추천과 사람의 선택을 구분하며, 미확인 효과·예산·일정·협의는 확정하지 않습니다. 구체화한 검토안은 ④ 실행 가능성 검토로 이어집니다.

⑤는 선택한 대안과 적용 범위, 선행 업무, 일정, 완료 기준, 역할, 자원을 입력합니다. 앞선 내용 유지 또는 미정으로 입력할 수 있으며, ④에서 남은 실행 조건은 확인할 역할·방법을 갖춘 준비 과업으로 정리하도록 요청합니다. 예산·담당·일정이 미정이면 승인이나 확보가 끝난 것으로 처리하지 않고, 근거가 있는 제안과 확인 필요 사항을 구분합니다.

⑥의 두 과정은 각각 5개 입력창을 제공합니다. **⑥-1**에서는 보고 목적·핵심 메시지·강조하거나 제외할 내용·기관 양식·분량 조건을 입력하며, 미리 개요를 작성할 필요가 없습니다. **⑥-2**에서는 개요 확정 여부와 수정 사항, 더할 생각·표현, 유지할 판단, 분량과 양식 조건을 입력합니다. 개요가 미확정이면 AI가 확인 요청과 수정 개요를 먼저 제시하고 본문 작성을 기다리도록 프롬프트에 명시합니다. 웹사이트 자체가 AI 채팅의 개요 확정 여부를 판별하는 기능은 아닙니다. 본문은 네 부분의 논리 연결을 유지하고 항목별 설명을 가급적 2줄 이내로 다듬되, 확정한 의미와 근거의 범위·불확실성을 유지하도록 요청합니다.

이전 단계 요약이나 채팅 이름을 다시 입력하는 항목은 없습니다. 결정 기록은 ①~⑥에서 단계마다 별도로 입력·생성합니다. 선택한 방안과 그 방안의 효과·비용·실행 조건이 확인되었는지는 구분합니다. 내 결정 기록은 해당 단계의 후속 요청이므로 공통 문구를 다시 반복하지 않습니다. ⑦에는 승인된 전체 문안을 그대로 제공하고 공통 문구를 추가하지 않습니다.

②-2의 **내가 분석한 내용**은 비워 둘 수 있습니다. 비운 항목은 생성된 프롬프트에 `사용자 분석 미입력`으로 표시되며, AI가 사용자 생각을 대신 입력한 것으로 처리하지 않습니다. 발행정보나 원문 내용을 확인할 수 없으면 확인 필요 상태로 남기도록 요청합니다. ②-1에서 AI가 문서를 제안했다는 것만으로 출처의 정확성·적합성·최신성이 보장되지는 않으므로 원문과 링크를 직접 확인해야 합니다. 웹 검색이나 첨부자료 읽기를 지원하지 않는 AI에서는 그 한계를 밝히고 확인되지 않은 문서명·링크를 만들지 않도록 구성했습니다.

생성 후 입력을 수정하면 다시 생성해야 복사할 수 있습니다. 입력과 생성 결과는 현재 페이지 안에서 작성 요령·입력·내 결정 기록을 오가거나, 단계·과정을 이동하거나, 창을 닫았다 열어도 유지되지만, **새로고침하거나 페이지를 닫으면 초기화됩니다.** 강사용에서는 준비된 기본 예시가 다시 채워집니다. 입력값은 페이지 메모리에서만 처리하며 로컬 저장소에 저장하거나 서버로 전송하지 않습니다. 이 사이트는 파일을 업로드받거나 AI API를 호출하지 않으며 웹 검색도 직접 수행하지 않습니다. 생성 버튼은 별도의 AI 채팅에서 사용할 프롬프트 본문을 만듭니다. 접속자마다 자신의 브라우저에서 독립적으로 사용합니다.

작성 요령과 예시는 학습을 위한 화면 안내이며 기본 프롬프트에 자동으로 덧붙이지 않습니다. 예시는 “청년 지원사업 모집공고의 신청정보 안내 개선”을 단계별로 이어가며 실제 조사 결과나 확정된 법·예산·일정을 의미하지 않습니다. 입력은 사용자의 실제 상황과 판단으로 작성합니다.

⑦도 웹사이트에서 HWPX를 생성하거나 파일을 업로드받는 기능이 아닙니다. Claude에서 사용할 수 있는 스킬·파일 편집·렌더링 기능에 따라 실행 가능 여부가 달라집니다. 첨부 양식이 없으면 요청하고, 기본 템플릿으로 임의 대체하지 않도록 구성했습니다. 프롬프트는 모든 표를 편집 가능한 표로 보존하고, 파일 구조 검증과 화면 배치 검증을 구분하며, 미검증 상태를 완료로 표시하지 않도록 요청합니다. 원고·표·주석·출처를 대조하고 실제 생성한 HWPX의 다운로드 링크를 받는 흐름입니다.

**전체 프롬프트 TXT 다운로드**는 사용자가 입력한 내용이 없는 기본 템플릿입니다. 수강생 화면과 입장 화면은 `prompts-student.txt`의 16개 문안을 제공합니다. 인증한 강사용 화면은 `prompts.txt`의 17개 문안을 제공하며 ⑦의 Claude 양식 작성·검증·다운로드 문안을 포함합니다. 두 파일의 ①~⑥·공통·결정 프롬프트는 같습니다.

## 먼저 열어보기

`index.html`을 브라우저에서 엽니다. 별도 설치나 빌드는 필요하지 않습니다. 폴더 구조를 유지해야 이미지·스타일·스크립트가 정상 표시됩니다. 브라우저에서 복사가 제한되면 화면 안내에 따라 선택된 내용을 Ctrl+C 또는 ⌘C로 복사하고, 모바일에서는 내용을 길게 눌러 복사합니다.

## GitHub Pages 배포

공개 저장소 `ankiyong/policy-report-six-steps`의 `master` 브랜치 루트에서 배포합니다.

1. 저장소 최상위에 입장 화면 `index.html`, 강사용 비밀번호 화면 `instructor-login.html`, 실습 화면 `practice.html`, 강의 화면 `instructor.html`, `.nojekyll`, `assets`, `images`, 강의 PDF, `prompts.txt`, `prompts-student.txt`, `content-plan.json`, `README.md`, `LICENSE.txt`, `TEMPLATE_README.txt`를 업로드하고 커밋합니다. 인증 스크립트·스타일과 강의 이미지·예시 데이터를 함께 배포해야 합니다.

이미지 시안·원본과 검토용 보드를 담은 `output` 폴더, ZIP 파일은 배포 대상에서 제외합니다. `tests` 폴더는 로컬 검증용입니다.

프롬프트를 수정하면 `content-plan.json`, `prompts.js`, `prompts.txt`, `prompts-student.txt`를 함께 맞춰 주세요. 수강생용 TXT에는 ⑦을 포함하지 않습니다. ①~⑥을 한 채팅에서 이어가는 방식에 맞춰 이전 단계 요약 입력을 제거하고 앞선 대화를 활용합니다. 원본 데이터의 `heading`과 단계별 `decisionHeading`은 현재 단계 번호·작업 이름입니다. 실제 프롬프트는 제목, 빈 줄, 해당 문안 순서로 구성합니다. ①·④의 메인 원문에는 공통 문구를 결합하고, ⑤에는 사용자가 승인한 공통 원칙까지 포함한 문안을 저장합니다. ②·③·⑥의 `processes`는 각 과정별 문안과 제목·공통 문구 포함 여부를 제공합니다. `includesCommon`인 문안에는 공통 문구를 중복으로 덧붙이지 않습니다. `repeatSection`은 자료별로 반복할 입력 영역을 가리킵니다. 결정 문구는 단계 제목과 결합해 각각 독립적으로 사용합니다.

⑥의 과정 ID는 `step-6-outline`, `step-6-body`입니다. 강사용 일반 진입은 개요 입력부터 시작하고, 본문 예시 바로가기의 `mode=instructor&process=body#step-6`에서만 본문 예시를 먼저 표시합니다. 개요 예시에는 이후의 본문 확정 결정을 붙이지 않습니다. 강사용 `report`는 `step-6-body`의 결과 예시와 일치하도록 유지합니다.

⑦의 과정 ID는 `step-7-main`, `kind`는 `document-workflow`, 단계의 `audience`는 `instructor`입니다. 원본 데이터 버전은 9이며 `includesCommon: true`로 별도의 공통 문구를 추가하지 않습니다. ⑦에는 입력 항목과 결정 프롬프트가 없습니다. 인증한 강사용 UI는 읽기 전용 프롬프트를 바로 복사할 수 있게 하고, 결정 프롬프트가 없는 단계를 처리합니다. 수강생의 단계 목록과 이동 범위에서는 ⑦을 제외합니다. 이미지 위치는 단계별 `image` 메타데이터를 우선 사용하며 ⑦은 `images/steps/step-6.webp`입니다. 강사용 예시의 `values`와 안내의 `fieldHints`는 빈 객체이며, 예시에는 실제 파일 생성·검증을 완료했다는 주장이나 가짜 다운로드 링크를 넣지 않습니다.

`writing-guides.js`의 `window.WRITING_GUIDES`는 과정 프롬프트 ID를 키로 사용합니다. 각 과정에 `goal`, `rules`, `examples`, `checkpoints`, `fieldHints`를 제공하며, `fieldHints`의 키는 실제 프롬프트 입력 항목명과 일치해야 합니다. 작성 요령을 수정할 때는 사용자 입력과 기존 프롬프트를 바꾸지 않고 안내 데이터만 수정할 수 있습니다.
