# 정책보고서 작성 · 6단계 채팅 가이드

기존 정책보고서 프롬프트 가이드의 카드와 좌우 입력창 디자인을 활용한 별도의 정적 웹사이트입니다. 단계마다 별도의 AI 채팅에서 작업하고, 사용자가 확정한 결정과 단계 결과 요약을 다음 채팅으로 이어갑니다. ② 자료 수집·분석은 같은 채팅 안에서 조사계획과 조사·해석 결과 정리의 두 과정으로 진행합니다.

- 공개 저장소: https://github.com/ankiyong/policy-report-six-steps
- GitHub Pages: https://ankiyong.github.io/policy-report-six-steps/


## 구성

- 공통 지침 + ① 주제·문제 설정 + ② 자료 수집·분석 + ③ 개선방안 도출 + ④ 실행 가능성 검토 + ⑤ 추진계획 수립 + ⑥ 보고서 작성: 총 7개 카드
- 공통 지침 1개, ①·③~⑥ 단계 프롬프트 5개, ② 과정 프롬프트 2개, 각 단계의 내 결정 기록 6개: 총 14개 프롬프트
- 각 단계에 준비할 자료·정보, 사람이 결정할 사항과 교육용 예시 제공
- ①·③~⑥에는 공통 문구 자동 포함, ②-1·②-2에는 사용자 제공 과정별 작성 지침 포함
- 단계별 “단계 프롬프트”와 “내 결정 기록” 탭, 항목별 입력, 생성 및 복사
- ②는 “②-1 조사계획 수립” → 직접 조사 → “②-2 조사·해석 결과 정리” 순서로 진행하며 “내 결정 기록” 탭도 유지
- ②-2는 자료별 입력 묶음을 추가·삭제해 여러 자료의 사실·출처·내 해석을 각각 입력
- 넓은 화면에서는 입력 영역과 템플릿·완성 프롬프트를 좌우에 배치하고 각각 스크롤
- 이전·다음 단계 이동, 기본 프롬프트 TXT 다운로드, 모바일 화면과 키보드 탐색 지원
- `#step-2` 등 단계 주소 공유 가능

## 사용 방법

1. **공통 지침**을 읽고 자료와 내 판단, 확인된 사실과 AI 제안을 구분하는 원칙을 확인합니다. ①·③~⑥에는 공통 문구, ②-1·②-2에는 과정별 작성 지침이 이미 포함되므로 별도로 덧붙일 필요가 없습니다.
2. 단계 카드를 열고 준비할 자료·정보를 확인합니다. **단계 프롬프트** 탭의 입력창을 채웁니다. ②는 **②-1 조사계획 수립**에서 먼저 조사 범위와 질문을 입력합니다. 모르는 정보는 `확인 필요`, 해당하지 않는 항목은 `해당 없음`으로 적습니다.
3. **프롬프트 생성**을 누르면 템플릿의 입력 자리에 작성한 정보가 들어갑니다. 완성된 본문을 확인하고 **프롬프트 복사**를 눌러 해당 단계의 새 AI 채팅에 붙여 넣습니다. 실제 자료 파일은 AI 채팅에 직접 첨부합니다. ②-1의 제안을 검토해 조사 대상을 정하고 직접 자료 검색·원문 확인·첫 해석을 수행한 뒤, **②-2 조사·해석 결과 정리**에 자료별 정보를 입력합니다. 생성한 ②-2 프롬프트는 **②-1과 같은 AI 채팅**에 붙여 넣습니다.
4. AI 답변을 읽고 **내 결정 기록** 탭에서 선택·확정한 사항과 이유, 수정·제외할 사항, 보류·추가 확인할 사항을 입력합니다. 생성한 결정 문구를 방금 답변을 받은 같은 단계의 AI 채팅에 보냅니다.
5. AI가 갱신한 **단계 결과 요약**을 복사합니다. 다음 단계에서는 별도의 AI 채팅을 열고 요약과 필요한 근거 자료를 전달합니다. 이전 채팅의 이름만 적으면 AI가 그 내용을 읽을 수 있다고 가정하지 않습니다.
6. ⑥ 보고서 작성에서도 내 결정 기록을 사용해 최종 확인 사항을 명시하고, 실제 기관 양식의 줄 수와 페이지 배치를 확인합니다.

결정 기록은 단계마다 별도로 입력·생성합니다. 선택한 방안과 그 방안의 효과·비용·실행 조건이 확인되었는지는 구분합니다. 내 결정 기록은 해당 단계의 후속 요청이므로 공통 문구를 다시 반복하지 않습니다.

생성 후 입력을 수정하면 다시 생성해야 복사할 수 있습니다. 입력과 생성 결과는 현재 페이지 안에서 단계·탭을 이동하거나 창을 닫았다 열어도 유지되지만, **새로고침하거나 페이지를 닫으면 초기화됩니다.** 입력값은 페이지 메모리에서만 처리하며 로컬 저장소에 저장하거나 서버로 전송하지 않습니다. AI API를 직접 호출하지 않으므로 생성 버튼은 AI 답변이 아닌 복사할 프롬프트 본문을 만듭니다. 접속자마다 자신의 브라우저에서 독립적으로 사용합니다.

**전체 프롬프트 TXT 다운로드**는 사용자가 입력한 내용이 없는 기본 템플릿입니다. 공통 문구, ①·③~⑥ 단계 프롬프트, ②-1·②-2의 과정별 프롬프트, 반복 사용하는 내 결정 기록이 들어 있습니다.

## 먼저 열어보기

`index.html`을 브라우저에서 엽니다. 별도 설치나 빌드는 필요하지 않습니다. 폴더 구조를 유지해야 이미지·스타일·스크립트가 정상 표시됩니다. 브라우저에서 복사가 제한되면 화면 안내에 따라 선택된 내용을 Ctrl+C 또는 ⌘C로 복사하고, 모바일에서는 내용을 길게 눌러 복사합니다.

## GitHub Pages 배포

공개 저장소 `ankiyong/policy-report-six-steps`의 `master` 브랜치 루트에서 배포합니다.

1. 저장소 최상위에 `index.html`, `.nojekyll`, `assets`, `images/steps`, `prompts.txt`, `content-plan.json`, `README.md`, `LICENSE.txt`, `TEMPLATE_README.txt`를 업로드하고 커밋합니다.
2. 저장소의 **Settings → Pages → Build and deployment**에서 **Source → Deploy from a branch**, **Branch → master**, **폴더 → /(root)**를 선택합니다.
3. 배포가 완료되면 Pages 주소에서 카드 이미지, 입력, 프롬프트 생성·복사, 내 결정 기록과 단계 이동을 확인합니다.

이미지 시안·원본과 검토용 보드를 담은 `output` 폴더, ZIP 파일은 배포 대상에서 제외합니다. `tests` 폴더는 로컬 검증용입니다.

공식 배포 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## 내용 수정

| 파일 | 수정할 내용 |
| --- | --- |
| `content-plan.json` | 사용자 제공 원문의 단계 구성, 준비 자료, 공통·단계·결정 프롬프트 |
| `assets/js/prompts.js` | 실제 화면에서 사용하는 카드 정보와 14개 프롬프트 |
| `assets/js/prompt-builder.js` | 입력 항목 추출과 입력값 치환 |
| `assets/js/guide.js` | 카드·대화상자·탭 표시, 입력과 생성·복사, 페이지 내 상태 |
| `assets/css/guide.css` | 색상·글꼴·카드·대화상자·반응형 배치 |
| `index.html` | 사이트 제목·설명·사용 안내 |
| `images/steps/common.webp`, `step-1.webp`~`step-6.webp` | 공통 지침과 6개 단계 이미지 |
| `prompts.txt` | 다운로드용 기본 문안 |

프롬프트를 수정하면 `content-plan.json`, `prompts.js`, `prompts.txt`를 함께 맞춰 주세요. 입력 토큰 외의 사용자 제공 프롬프트 원문은 유지합니다. ①·③~⑥의 메인 프롬프트는 각 단계 원문 뒤에 공통 문구를 결합합니다. ②의 `processes`에는 과정별 작성 지침을 포함한 원문을 저장하며 공통 문구를 중복으로 덧붙이지 않습니다. 런타임의 `step-2-plan`과 `step-2-analysis`는 각각 해당 원문을 `text`로 사용합니다. `repeatSection`은 자료별로 반복할 입력 영역을 가리킵니다. 결정 프롬프트는 공통 결정 문구를 단계마다 독립적으로 사용합니다.
